# Правила связи агентов — 3 октября 2026

## Причина

Вступление глобального Huddle Skill предлагало комнату почти для любого обмена между несколькими агентами. Это противоречило правилу встроенной координации внутренних субагентов в harness-routing.

## Применённое решение

- Внутренние дочерние агенты текущей задачи используют встроенную координацию своего харнеса. В Codex — доступные инструменты collaboration; отдельная комната или CLI-процесс для этого не создаётся.
- Для отдельного существующего чата того же или другого харнеса приоритет у доступного прямого нативного инструмента доставки. Проверяются адресат, поддержка инструмента и разрешение на отправку.
- При отсутствии такого инструмента используется подходящий Huddle message_send. Он тоже может выбрать нативный транспорт; доставка через Huddle не обязательно означает комнату.
- Постоянная общая история и выбранный протокол совета, эстафеты, команды или роя остаются в Huddle. Пробовать другой транспорт перед осознанно выбранной комнатой не требуется.
- Запрет отправки не является технической недоступностью и не разрешает переход на другой инструмент.

## Где применено

Канонические файлы AgentSync: skills/global/huddle/SKILL.md и skills/global/harness-routing/SKILL.md.

Оба файла точечно синхронизированы в ~/.codex/skills, ~/.claude/skills и ~/.gemini/antigravity-cli/skills. OpenCode Huddle использует существующую ссылку ~/.config/opencode/skills/huddle на канон. Неактивные каталоги и посторонние Skills не изменялись.

## Проверка

- Astra (gpt-6-astra) предложила решение и независимо проверила подготовленные точные diff: GO, существенных дефектов нет.
- Применение проверило исходные SHA-256 перед записью, затем прочитало все восемь файлов обратно.
- Подтверждены равенство установленных копий канону, ссылка OpenCode и сохранение двух прежних исправлений harness-routing: диагностика авторизации в песочнице и обработка разрешений дочернего Claude.
- git diff --check для двух канонических файлов прошёл.
- Jev для выбора области триггера вернул fallback/budget_unavailable; повторов не было. Решение принято с Astra.

Это изменение инструкций, не программная блокировка транспорта. Проверки внешних моделей, доступности каждой сессии и нового поведения всех харнесов не проводились. Новые правила будут доступны агенту при следующей загрузке Skill; уже загруженный контекст автоматически не переписывается. Сервер Huddle не изменялся и не перезапускался.
