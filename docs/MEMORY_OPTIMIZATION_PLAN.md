# Оптимизация памяти — рабочий контракт

Дата: 2026-10-05. Задача: #18. Ветка: `work/huddle-memory-sqlite`.

## Решение пользователя и область

«делай в новой ветке»: снизить память через единый сервер, SQLite и загрузку
переписки частями. 20 МБ — неподтверждённая цель, не обещание. Публикация новой
ветки и слияние отдельно не запрошены.

## Условия приёмки

1. Один процесс обслуживает существующие адреса 8014 и 45111; MCP-подключения,
   переподключение, защита доступа и единственный наблюдатель сохраняются.
2. SQLite сохраняет ID, ответы, защиту повторов; есть проверяемая миграция,
   резервное копирование и путь возврата. Старые писатели не теряют сообщения.
3. Дашборд показывает страницы старой/новой истории без неограниченного
   накопления сообщений в памяти; старая форма API остаётся совместимой.
4. Адресные сценарии, проектные проверки и независимый просмотр успешны.
5. Замер до/после отделяет серверы, исполнителей и неизмеренную вкладку браузера.

## Предположения и риски

- HTTP-приложение уже содержит MCP; поддержку двух сокетов проверяем на
  установленной версии uvicorn, не выводим только из наличия HTTP-режима.
- Нельзя считать SQLite-переключение переменной среды защитой от старого
  процесса, продолжающего писать JSONL. Миграция требует отдельной защиты.
- Метаданные и права не перепроектируются без необходимости: первый этап
  SQLite касается истории сообщений.
- Историческое объяснение SQLite-lock не доказано для текущего JSONL-кода.
- Live-настройка и данные остаются прежними до изолированной приёмки.

## Исполнители и следующий шаг

`sqlite_storage`: bus/SQLite/миграция/копии; `single_server`: CLI/два сокета/
развёртывание; `paged_dashboard`: API/переписка страницами. Консультация Claude:
`room_e21f937c`. Ведущий интегрирует и проверяет итог.

Остановить до живой миграции, если нельзя доказать сохранность истории или
совместимость клиентов. После выполнения условий не расширять проверки
и не переписывать несвязанные части продукта.

## Дополнение: предпочтение встроенной связи

Пользователь попросил отказ Huddle с подсказкой, если конкретное обращение
можно выполнить встроенным инструментом агента. Исполнитель `native_route_guard`
готовит отдельное изменение прямой пересылки. Сервер не видит каталог инструментов
клиента: доступность маршрута должна быть явно сообщена для точного адресата.
Это декларация клиента, а не независимо подтверждённая возможность.

Приёмка: известный прямой маршрут получает `native_route_required` и название
инструмента без отправки; неизвестный маршрут сохраняет совместимость; общие
комнаты и режимы не блокируются. Проверки прав остаются обязательными.
Автоматический запрет для любого Codex по одному имени среды недопустим.
