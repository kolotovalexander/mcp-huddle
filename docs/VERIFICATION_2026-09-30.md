## Найдено и исправлено

- Диагностика Huddle попадала в stdout протокола MCP и вызывала
  `Failed to parse JSONRPC message`. Исправлено в `474f9b3`, мост перезапущен.
- Подписочный профиль Claude разрешал `message_post`, но не
  `swarm_pilot_round_done`, поэтому совет зависал после ответа. Команда
  завершения раунда добавлена только в allowlist подписочного профиля.
  После перезапуска успешный совет подтверждён в `room_7599e25e`.
- OpenCode не обнаруживал Huddle Skill при
  `OPENCODE_DISABLE_CLAUDE_CODE_SKILLS=1`. Создана ссылка из
  `~/.config/opencode/skills/huddle` на канонический каталог AgentSync.
  Штатный `opencode debug skill` показал Skill `huddle` в этом каталоге.

## Ограничения, которые остаются

- В `room_ae166754` автоматическая проверка доступа Codex отклонила
  `message_post` одного участника, не увидев пользовательского разрешения
  в контексте дочерней CLI-сессии. Обхода не было; Huddle правильно отказал
  в `round_done` без результата. Другие Codex-ходы успешно завершились.
  Следовательно, универсальный беспроблемный запуск Codex пока не подтверждён.
- Codex из `/private/tmp` завершился с `Not inside a trusted directory`.
  Успешные сценарии использовали существующую Git-рабочую копию Huddle.
- Hermes и MiMo не имеют включённых spawn-профилей в проверенном реестре.
  Их нельзя считать проверенными участниками Huddle.
- Наличие Skill у Claude, Codex и Antigravity проверено по файлам; текущий
  Codex видит Skill в каталоге доступных Skills. Подписочный reviewer Claude
  запускается с ограниченным окружением и получает протокол в промпте.
- Не проверялись запись файлов, subworktree, замена по лимитам, дочерние
  агенты и каждый модельный вариант OpenCode. Это отдельные сценарии.
