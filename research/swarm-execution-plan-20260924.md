# Huddle Swarm: план доведения функций

24 сентября 2026. Источник требований — [решения Александра](swarm-user-decisions-20260924.md). Исходный срез — [пилот и его ограничения](swarm-mode-plan-v3-20260923.md). Это рабочая очередь, а не заявление о готовности.

## Принцип исполнения

Каждый этап заканчивается пользовательским поведением, а не серией проверок внутренних деталей. Исполнители работают в отдельных Git worktree. Claude ведёт основные реализации; Antigravity и OpenCode получают независимые узкие задачи после проверки доступности их маршрутов. Координатор интегрирует изменения, сохраняет пользовательские решения и проводит один-два сквозных сценария на функцию. Старые тесты используются как регрессионный барьер, новые добавляются только для публичного поведения или значимого сбоя.

## Обязательная проверка перед приёмкой

1. Четыре режима: один короткий сценарий показывает порядок приглашений, явное завершение раунда и право последнего слова в совете.
2. Файлы и права: одна маленькая Git-папка, два участника, общий каталог и вариант с дополнительными копиями; неподдерживаемый профиль и отсутствующий Guard отклоняются до запуска.
3. Отказ и замена: один отказ модели даёт не больше одной допустимой замены, прежний дочерний процесс остановлен, роль и сообщения сохраняются. Запрос разрешения не одобряется автоматически.
4. Дашборд: видно режим, роли, ход участников и итог; технический журнал не подменяет пользовательский статус.
5. Граница выпуска: проверка компиляции Python и синтаксиса JS, затем полный проектный набор только при выпуске или если адресные сценарии оставят существенный риск.

На работающем сервере `:8014` проверены HTTP 200 для `/dashboard`, `/api/rooms` и выбранной комнаты. В старой вкладке `127.0.0.1` динамические запросы браузера зависли, хотя терминальный запрос отвечал; новая фоновая вкладка с тем же адресом тоже не восстановилась. Через `http://localhost:8014` комната ранее загрузилась. Кнопка «Ответить» выбрала точное сообщение #2, переключила форму на комментарий и показала адресата; отправку не выполняли. При новом скрытом открытии 25 сентября даты и кнопки ID/имени были видны, но один повторный reload снова временно показал ноль комнат при HTTP 200 `/api/rooms`. Это подтверждает элементы интерфейса, но не устойчивую загрузку браузера и не реальное копирование из скрытой вкладки. Нужен диагноз соединений браузера, если сбой повторится у пользователя; не подменять его предположительной правкой.

Следующий короткий маршрут: закрепить модель и усилие в выбранных постоянных профилях комнаты; затем реализовать ограниченных дочерних агентов и привязку имени участника к его нативной сессии. Сообщение во время занятого одноразового CLI уже сохраняется в журнале комнаты и после выхода дочернего процесса передаётся следующему ходу; живого ввода в работающий процесс нет. Совет уже хранит запрос на последний ответ организатора, но не умеет будить его после закрытия его сессии: это отдельный разрыв. `mcp_url` закрепляет прямой Huddle-маршрут Codex при первом запуске и теперь сохраняется для `codex exec resume`; другие глобальные MCP остаются доступны. Исправление ID проверено адресным чтением прежней комнаты, но живой агент в успешном сценарии использовал имя, поэтому прямая приёмка вызова с ID остаётся отдельным узким пробелом. Полный набор тестов запускать на выпускном рубеже или при обнаруженном системном риске, не после каждого шага.
