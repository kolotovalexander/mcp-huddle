# Huddle Swarm: план доведения функций

24 сентября 2026. Источник требований — [решения Александра](swarm-user-decisions-20260924.md). Исходный срез — [пилот и его ограничения](swarm-mode-plan-v3-20260923.md). Это рабочая очередь, а не заявление о готовности.

## Принцип исполнения

Каждый этап заканчивается пользовательским поведением, а не серией проверок внутренних деталей. Исполнители работают в отдельных Git worktree. Claude ведёт основные реализации; Antigravity и OpenCode получают независимые узкие задачи после проверки доступности их маршрутов. Координатор интегрирует изменения, сохраняет пользовательские решения и проводит один-два сквозных сценария на функцию. Старые тесты используются как регрессионный барьер, новые добавляются только для публичного поведения или значимого сбоя.

## Обязательная проверка перед приёмкой

1. Четыре режима: один короткий сценарий показывает порядок приглашений, явное завершение раунда и право последнего слова в совете.
2. Файлы и права: одна маленькая Git-папка, два участника, общий каталог и вариант с дополнительными копиями; неподдерживаемый профиль и отсутствующий Guard отклоняются до запуска.
3. Отказ и замена: один отказ модели даёт не больше одной допустимой замены, прежний дочерний процесс остановлен, роль и сообщения сохраняются. Запрос разрешения не одобряется автоматически.
4. Дашборд: видно режим, роли, ход участников и итог; технический журнал не подменяет пользовательский статус.
5. Граница выпуска: проверка компиляции Python и синтаксиса JS, затем полный проектный набор только при выпуске или если адресные сценарии оставят существенный риск.

На работающем сервере `:8014` проверены HTTP 200 для `/dashboard`, `/api/rooms` и выбранной комнаты. Ранее один повторный reload скрытой вкладки временно показал ноль комнат при HTTP 200 `/api/rooms`; причина эпизода не подтверждена, правок наугад не вносили. Позднее после `4f14a01` новая скрытая загрузка показала 103 комнаты, полные даты, кнопку копирования ID и завершённых участников `room_3fee1b9b` в обеих панелях. Копирование в скрытой вкладке не подтверждалось из-за отсутствия фокуса; адресный ответ выбрал точную реплику и показал адресата, но отправку не выполняли.

Следующий маршрут: сделать явную политику возобновления ребёнка вместо нынешнего одноразового запуска и надёжный повтор доставки при временном сбое. Для конфиденциальной истории нужна настоящая изоляция доступа к локальным файлам и другим MCP: нынешний выбор `history` управляет только переданным контекстом. Пока `swarm_whoami` подтверждён только для Codex с прямым HTTP MCP; Claude, stdio и агрегаторы не получают эту личность. При включённом `MCP_HUDDLE_TOKEN` транспортная авторизация настраивается отдельно и не заменяется секретом участника. Участников можно назвать независимо от профиля: несколько имён теперь выбирают один профиль; для разных моделей нужны отдельные профили. Сообщение во время занятого одноразового CLI сохраняется в журнале комнаты и после выхода дочернего процесса передаётся следующему ходу; живого ввода в работающий процесс нет. В совете организатор с доступным профилем реестра получает слот пробуждения для последнего ответа: это новая CLI-сессия с историей комнаты, а не возобновление его исходной сессии; организатор без профиля отвечает после возвращения. `mcp_url` закрепляет прямой Huddle-маршрут Codex при первом запуске и сохраняется для `codex exec resume`; другие глобальные MCP остаются доступны. Исправление ID проверено адресным чтением прежней комнаты, но живой агент в успешном сценарии использовал имя, поэтому прямая приёмка вызова с ID остаётся отдельным узким пробелом. Полный набор тестов запускать на выпускном рубеже или при обнаруженном системном риске, не после каждого шага.
